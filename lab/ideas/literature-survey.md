# Literature survey: methods that transfer to "21" (21 Theorist)
All URLs below were opened (HTTP 200 or search-result text read) on 2026-11-18. "Transfers" = my judgement, not a measured result.
The project's own earlier survey (`engine/twentyone-solver/research_notes/…`, `reports/Stronger 21 engine methods.md`) is an UNVERIFIED claim set; where I repeat one of its sources I re-opened it myself.

|---|---|---|---|
| **Poker Squares** (closest relative: place each of 25 drawn cards, deck known, sum of independent line scores). Neller, EAAI NSG Challenge; Gettysburg player: Neller et al., "Learning and Using Hand Abstraction Values for Parameterized Poker Squares", AAAI/EAAI 2016. https://ojs.aaai.org/index.php/AAAI/article/view/9859 , http://cs.gettysburg.edu/~tneller/papers/eaai16.pdf | Learned expected final score of an *abstraction of each row/column* (hand size, rank counts, undealt-rank counts, flush/straight potential) by Monte-Carlo ε-greedy self-play; board value = sum of independent line estimates; played with depth-2 expectimax on that evaluator. Best of the contest field. | Same structure as 21: board value ≈ sum of 4 column values, each column abstracted by (cards, soft/hard total, how many cards of the needed ranks are still undealt). **Own measurement:** a purely additive per-column table (my `td.rs`, 6M TD games) plays only 5,857 ± 16 at 0-ply and 6,777 ± 14 at 1-ply on 10,000 of Landon's shuffles — far below the 8.6k NN — so *pure additivity is not enough in 21*; column interactions (two columns needing the same rank; shared tens) must be in the evaluator. | `ntuple-column-evaluator.md` |
| **2048** n-tuple TD. Szubert & Jaśkowski, "Temporal Difference Learning of N-Tuple Networks for the Game 2048", IEEE CIG 2014. https://www.cs.put.poznan.pl/mszubert/pub/szubert2014cig.pdf (search text read; direct curl 403) | *Afterstate* value function V(s') with n-tuple lookup tables (17 four-cell tuples, 860,625 weights), TD(0), learning rate 0.0025 best, >97% wins at 1-ply, no search. | 21 has a natural afterstate (placement + Stay, before the next card). Lookup tables over (column-state pairs/triples × stage) are cheap to evaluate (a few table reads) so a 1–2-ply search can run 100× faster than the 56-128-48 MLP, which buys deeper/wider search or exact solve from earlier. | `ntuple-column-evaluator.md` |
| **2048** advanced. Jaśkowski, "Mastering 2048 with Delayed Temporal Coherence Learning, Multi-Stage Weight Promotion, Redundant Encoding and Carousel Shaping", IEEE T-CIAIG 2018. https://arxiv.org/abs/1604.05085 ; Yeh, Wu, Hsueh et al., "Multi-Stage Temporal Difference Learning for 2048-like Games", https://arxiv.org/abs/1606.07374 | Separate weight sets per game *stage*; **carousel shaping** = start training episodes from saved states of later stages so late-game states are visited enough; TC learning rates. | 21 has a clean clock (cards left). Stage = cards-left bucket; exact endgame results (cheap to generate from 14 cards) can seed late-stage training positions (carousel). The Learner owns this; I only state the transfer. | `ntuple-column-evaluator.md` |
| **Solitaire Yahtzee** exact DP. Verhoeff's page https://www-set.win.tue.nl/~wstomv/misc/yahtzee/trivia.html (optimal mean 254.5896…); Glenn (Loyola TR-0002 2006; page not reachable from the box, cited by Verhoeff/others). | Solved exactly after reducing state to a minimal statistic; **the optimal policy's departures from greedy are concentrated in managing the 35-point upper-bonus** (a threshold/"progress to bonus" state variable). | Perfect Bonus (+1000 while zero busts) is the 21 analogue: a binary state flag worth up to 1000. I computed its exact value (below): it is the largest single "state flag" in the game, and a learner that sees only `busts==0` as one input bit must learn its decay with cards left. Suggests explicit input features: P(no further bust under careful play) and exact life values per cards-left. | `life-margin-schedule.md` |
| **Pig** optimal roll/hold. Neller & Presser, "Optimal Play of the Dice Game Pig", UMAP J. 25(1) 2004. https://cs.gettysburg.edu/~tneller/papers/pig.pdf (text read) | "Hold at 20" maximises expected points *per turn* but is not optimal for the real objective; state-dependent value iteration gives the true rule. | Risk rules of thumb ("bust penalty +300/+600") are per-decision myopic; the right price of a bust depends on (busts so far, cards left, Stays left). Landon's flat penalties are the "hold at 20" of 21. | `life-margin-schedule.md` |
| **Can't Stop** stop rules. Glenn & Aloi, "A Generalized Heuristic for Can't Stop", FLAIRS 2009. https://cdn.aaai.org/ocs/123/123-2430-1-PB.pdf (text read) ; Keller's *Rule of 28* | A one-number threshold rule on a progress score (Rule of 28) is a strong heuristic; a genetic algorithm tuning *weights + threshold* beat it by ~18–19% (9.12 vs 10.74 turns) and was checked against exact solutions of small variants. Solving the real game is infeasible; solved small variants serve as ground truth. | (a) The Stay decision is a stop-rule: threshold on "how bad is my best plain placement" that varies with cards left → tune a 3–6-parameter schedule by direct paired search (GA/CEM), not by hand. (b) Use exactly solvable small decks as a unit test for evaluators (the engine README already does one 13-card test). | `stay-margin-schedule.md` |
| **Information relaxation** (ceiling only). Brown, Smith & Sun, Operations Research 58(4), 2010. https://pubsonline.informs.org/doi/10.1287/opre.1090.0796 (search text read; direct curl 403) | Clairvoyant upper bounds become tight if penalised by a martingale-difference term from an approximate value function. | Not a policy method; relevant to the lead's ceiling work (clairvoyant mean is a loose bound, penalised version is tighter). Not used by me. | — |
