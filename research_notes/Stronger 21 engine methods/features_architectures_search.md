# Input features, network architectures and search enhancements for a value function over "21" solitaire states (known deck composition)

Reading notes: "Cited Findings" are facts taken from the linked source (most were checked against the paper full text this session; where only the abstract or a search snippet was checked, that is stated). "Inferences" are my own reasoning about applicability to this game and are NOT sourced. Cost estimates for JavaScript are my own back-of-envelope figures, not measurements.

## 1. Permutation-invariant / set architectures for the 4 interchangeable columns

### Takeaway
Building the column symmetry into the model (canonical sort, shared per-column encoder + pooling, or weight sharing over symmetric copies) is a standard, nearly free way to improve generalisation; the literature supports "converges faster / generalises better" qualitatively, but I found no controlled card-game ablation quantifying it. Plain sum/mean pooling loses cross-element interactions, so the pooled encoder must either see global context (deck, busts, streak) per column or be followed by an interaction stage.

### Cited Findings
- Deep Sets: the paper's main theorem "characterizes the permutation invariant functions" and yields a family of functions with a special structure that gives a deep architecture operating on sets (abstract verified; the well-known form is f(X) = rho(sum_i phi(x_i)), recalled from the paper body, not re-read this session) — [Zaheer et al. 2017, arXiv 1703.06114](https://arxiv.org/abs/1703.06114)
- Set Transformer motivation: in set pooling "every element in a set is processed independently ... some information regarding interactions between elements has to be necessarily discarded", which "can make some problems unnecessarily difficult"; self-attention blocks encode pairwise and (stacked) higher-order interactions; full self-attention is O(n^2), induced-point attention is O(nm) — [Lee et al. 2019, arXiv 1810.00825](https://arxiv.org/pdf/1810.00825)
- Choice of pooling operator matters a lot when the target is not additive: on a "regress the max of a set" toy task, mean pooling MAE 2.133, sum pooling 1.902, max pooling 0.1355, attention (SAB+PMA) 0.2085 — [Lee et al. 2019, Table 1](https://arxiv.org/pdf/1810.00825)
- On Omniglot unique-character counting, pooling-only variants reach ~0.44-0.46 accuracy; the paper presents the self-attention encoder variants as the improvement over these (I verified the pooling baselines 0.4382 / 0.4617 / 0.4359 and the PMA variant 0.4572; the SAB rows were cut off in my extract) — [Lee et al. 2019, Table 2](https://arxiv.org/pdf/1810.00825)
- Symmetry by weight sharing in lookup-table evaluators: in 2048 n-tuple networks "each n-tuple is employed eight times for each possible board rotation and reflection. Symmetric sampling facilitates generalization and improves the overall performance of the learning system without the expense of increasing the size of the model" — [Jaśkowski 2016, arXiv 1604.05085](https://arxiv.org/pdf/1604.05085)
- Equivariant networks "converge faster than unstructured baselines on CartPole, a grid world and Pong"; building symmetry in reduces the size of the solution space (abstract only; no numbers given there) — [van der Pol et al. 2020, arXiv 2006.16908](https://arxiv.org/abs/2006.16908)
- Object-exchangeability paper: when inputs are ordered sets, permutation invariance "must be learned during training"; a permutation-invariant attention abstraction is hypothesised to be more sample efficient (search snippet only) — [Mern, Sadigh, Kochenderfer, arXiv 1905.02698](https://ar5iv.labs.arxiv.org/html/1905.02698)
- A multi-agent permutation-invariant network paper reports sample-efficiency gains "up to 400%" over baselines (search snippet only; multi-agent RL, not card games) — [Hao et al., arXiv 2203.05285](https://arxiv.org/pdf/2203.05285v1)
- KataGo: adding global pooling layers (mean, board-size-scaled mean, max of each channel) so local computations can condition on global context; removing global pooling cost about 176 Elo (1329 -> 1153) at equal training and a ~1.60x increase in training time to reach the same strength — [Wu 2019, arXiv 1902.10565, Table 2](https://arxiv.org/pdf/1902.10565)

### Inferences
- With only n = 4 columns, three options are all far below 20 microseconds: (a) canonicalise by sorting columns on a fixed key before a plain MLP (zero runtime cost, removes a 24x redundancy in the input space; downside: sort discontinuities at ties/swaps); (b) Deep-Sets style: shared phi(column_i, global context) for each column, pooled with sum AND max concatenated, then rho; (c) pairwise terms sum over i<j of psi(col_i, col_j) (6 pairs) as a cheap stand-in for attention. Full attention is unnecessary at n = 4.
- The max-regression result above is directly relevant: quantities like "best column for the next card" or "is there any safe column for a 10" are max/any-type functions of the columns, which sum pooling approximates poorly. Pool with both sum and max (KataGo also pools mean and max).
- Columns compete for the same cards (two columns both needing a 5 share the same outs), so the value is not additively separable. Feed each column's phi the full deck vector and global scalars, and keep an interaction stage after pooling; pure sum-of-independent-column values will have a structural error floor.
- If the current 56 handcrafted inputs present the columns in arbitrary order, a 4x larger MLP would not fix that: the net must learn the same function 24 times. This is consistent with (but does not prove) the observed plateau.

### Gaps
- No controlled ablation found of permutation-invariant vs ordered encodings in a card or solitaire game. A 2026 Big 2 paper (arXiv 2605.28863) uses a self-attention hand encoder but the snippet showed no ablation.
- Sorting vs pooling: I found no direct empirical comparison; the recommendation above is inference.

## 2. Representing deck composition; outs / interaction features; NNUE-style sparse and n-tuple lookup features

### Takeaway
Strong card-game nets use one-hot-per-count (not raw scalars) for card counts, and the fastest high-capacity evaluators in 2048 and chess are sums of table lookups over sparse, incrementally updated features rather than dense MLPs. A lookup/NNUE-style first layer indexed by (column state x card value x remaining count) is the most promising cheap route to capture column-deck interactions here.

### Cited Findings
**How card-game AIs encode counts**
- DouZero (DouDizhu): "Cards for both states and actions are encoded into a 4x15 one-hot matrix, where columns correspond to the 13 ranks and the jokers, and each row corresponds to the number of cards of a specific rank"; suits are dropped because they are irrelevant. Other state features are one-hot vectors: number of cards left for each other player (size 17 or 20), number of bombs so far (size 15), plus card matrices for played cards and the union of other players' hands. Net: LSTM over recent moves + 6-layer MLP of width 512 — [Zha et al. 2021, arXiv 2106.06135](https://arxiv.org/pdf/2106.06135)
- Hanabi Learning Environment: observations are a bit string; wrappers describe remaining deck size in unary/"thermometer" encoding (JaxMARL: "Deck: 40, thermometer") and the discard pile as cumulative bits per colour/rank; each card is a 25-bit one-hot — [PettingZoo Hanabi docs](https://pettingzoo.farama.org/environments/classic/hanabi/), [HLE paper](https://ar5iv.labs.arxiv.org/html/1902.00506) (the paper itself only confirms the bitstring observation; the encoding details come from the wrappers' docs via search snippets)
- Blackjack: one preprint feeds a network the true count plus per-card-value remaining proportions (11 inputs) for bet sizing; a blog write-up found adding count information did not help a hit/stand network and "sometimes confused it" (anecdotal, not peer-reviewed) — [arXiv 2511.19628](https://arxiv.org/pdf/2511.19628), [Towards Data Science post](https://towardsdatascience.com/counting-cards-with-a-neural-net-ce426c2b6e57)
- TD-Gammon-style evaluators add a few handcrafted aggregate inputs to the raw encoding: a Dice-game net used 50 raw inputs plus 4 inputs counting "runs" of length 2 and 3 per player, with only 10 hidden units — [Veness & Blair 2007](https://cgi.cse.unsw.edu.au/~blair/pubs/2007VenessBlairCIG.pdf)

**NNUE (sparse, incrementally updated first layer)**
- The first-layer output (accumulator) is stored and updated per move: removing a feature subtracts its weight column, adding a feature adds it; "when the network is scaled in size the inputs must become sparse"; best architectures have input sparsity "in the order of 0.1%" — [Stockfish nnue-pytorch docs](https://raw.githubusercontent.com/official-stockfish/nnue-pytorch/master/docs/nnue.md)
- HalfKP features are tuples (own king square, piece square, piece type, colour) = 64*64*5*2 = 40,960 features, i.e. a deliberately "crossed" feature (every piece conjoined with king position); a 256x2->32->32->1 net over it has ~10M first-layer parameters (~20 MB quantised); Stockfish later moved to 1024x2->8->32->1 — [same docs](https://raw.githubusercontent.com/official-stockfish/nnue-pytorch/master/docs/nnue.md)
- Quantisation: int16 accumulator, int8 weights later, clipped ReLU to 0..127 — [same docs](https://raw.githubusercontent.com/official-stockfish/nnue-pytorch/master/docs/nnue.md)
- Feature factorisation: during training add coarser "virtual" features that share weight across many real features (e.g. piece-square without king) so related sparse features learn a common component faster; they are summed into the real weights after training and "seem to only be relevant in the early stages" — [same docs](https://raw.githubusercontent.com/official-stockfish/nnue-pytorch/master/docs/nnue.md)
- Stockfish 12 (first NNUE release) "will typically win at least ten times more game pairs than it loses" vs Stockfish 11; NNUE nets "can be very efficiently evaluated on CPUs" — [Stockfish 12 blog](https://stockfishchess.org/blog/2020/stockfish-12/). Chess.com reported more than 100 Elo within a month of integration — [chess.com news](https://www.chess.com/news/view/stockfish-absorbs-nnue-100-elo)

**n-tuple networks (pure lookup-table value functions) in 2048**
- Definition: V(s) = sum over tuples i of V_i[index_i(s)], where the index is the base-c number formed by the cell values at the tuple's locations; no hidden layer at all — [Jaśkowski 2016](https://arxiv.org/pdf/1604.05085)
- Speed: the best network plays 258,371 moves/s at 1-ply and 20,524 moves/s at 2-ply on a single i7-4770K thread (i.e. a few microseconds per move including move generation) — [Jaśkowski 2016, Table V](https://arxiv.org/pdf/1604.05085)
- Capacity: four 6-tuples = 4*16^6 = 67,108,864 weights; a 5x 7-tuple net = 1,342,177,280 weights — [Jaśkowski 2016](https://arxiv.org/pdf/1604.05085)
- Gains by technique (average score, 1-ply / 3-ply): TD(0.5) 140,397 / 234,997 -> TC(0.5) adaptive learning rates 248,770 / 333,010; 1 stage 251,033 / 296,207 -> 24 stages with weight promotion 267,544 / 400,124 (24 stages WITHOUT promotion was worse at 1-ply: 226,352); adding redundant (smaller, overlapping) tuples 42-33 -> 42-33-4-22-3: 265,435 / 393,289 -> 319,433 / 469,779; with carousel shaping 311,426 / 491,398 — [Jaśkowski 2016, Tables II-IV](https://arxiv.org/pdf/1604.05085)
- "Redundant encoding facilitates generalization and, as a result, the learning speed and the final controller score"; redundant tuples can be folded into the larger ones after training so the final agent is not slower — [Jaśkowski 2016](https://arxiv.org/pdf/1604.05085)
- Stage-specific evaluators come from Buro's Logistello (Othello) and "pay off only when additional generalization methods are applied" (weight promotion = initialise a stage's weights from the previous stage) — [Jaśkowski 2016](https://arxiv.org/pdf/1604.05085)
- A single large network (421-43, 1.34G weights) was best at 1-ply (284,657) but poor at 3-ply (326,267), which the author calls a "1-ply overfitting syndrome": accuracy under greedy play does not guarantee strength inside search — [Jaśkowski 2016, Table III](https://arxiv.org/pdf/1604.05085)
- Prior best 2048 players combined an n-tuple network with hand-made features (Yeh et al.: 443,526 at 3-ply) — [Jaśkowski 2016, Table VI](https://arxiv.org/pdf/1604.05085)

### Inferences
- Count encoding: replace the 10 raw remaining-count scalars with one-hot (or thermometer) per count: 9 values x 5 levels (0-4) + ten-value x 17 levels (0-16) = 62 binary inputs. One-hot lets a first layer learn arbitrary non-linear per-count effects (e.g. "no 7s left" kills the three-7s bonus; "exactly zero cards of value 21-total" kills a column's direct outs), which a linear function of a raw count cannot express. Thermometer gives smoother generalisation between neighbouring counts. Also provide probabilities count/N_remaining, since the same count means different things at 40 vs 8 cards left.
- "Outs"/hypergeometric features, O(10) per column, all computable from the deck vector: (i) p_hit21 = count[21 - total] / N (plus the ace route for soft totals); (ii) p_bust = sum of count[v] for v > 21 - hard_total, / N; (iii) p_safe_and_fifth_card = probability the next card completes five cards without busting; (iv) expected number of deals before any out appears, N+1 over outs+1 (standard hypergeometric waiting-time result; unsourced here); (v) P(at least one out in the next k cards) = 1 - C(N - outs, k)/C(N, k) for k = 2, 4, 8; (vi) for 7s: count[7] and whether a column is still all-sevens. Global features: fraction of deck that busts every column ("dead card" mass, which forces a bust or a Stay), fraction that scores somewhere, number of distinct column needs that collide on the same card value.
- NNUE-style design for this game: define sparse feature f(column_state, card_value v, remaining_count_of_v). Column state space is small (hard total x soft flag x card count x all-sevens: on the order of 100-200 reachable states); with 10 values and <=17 count levels this is roughly 150 x 62 ~ 10k features, of which exactly 4 x 10 = 40 are active per position (0.4% sparsity, the regime NNUE targets). Sum their weight rows into a width-64..256 accumulator (sum over columns = automatic permutation invariance, i.e. a Deep Sets phi implemented as a table), add global-state rows (busts, stays, streak, cards-left bucket), then clipped ReLU -> 32 -> 1. This is exactly the "crossed feature" trick of HalfKP (piece x king) transferred to (column x deck count).
- Incremental update: dealing a card of value v to column c changes column c's 10 features (remove 10, add 10) and, for the other 3 columns, only the feature for value v (count changed): 26 row add/subtracts instead of 40. In expectimax this is a modest saving; even from-scratch accumulation is 40 rows x 128 int16 = ~5k adds, which I estimate at roughly 2-5 microseconds in JS with Int16Array/Float32Array (estimate, unmeasured). The whole net should fit in the 20 microsecond budget up to accumulator width ~256.
- Pure n-tuple alternative (even faster, sub-microsecond): V = sum of LUT entries over tuples such as (column state, count[21-total], count[10]) per column; (sorted pair of column totals, count of the card both need); (busts, stays, streak bucket, cards-left bucket); (bucketed counts of 10s, aces, 7s, low cards). Redundant small tuples improved 2048 play substantially, so include overlapping coarse and fine tuples. Tables for this game are tiny (thousands to a few million entries) compared with 2048's 67M+.
- Factorisation transfers directly: train with extra virtual features (column_state alone; (v, count) alone) so rarely seen (state, v, count) triples inherit sensible values.
- Stage-splitting (separate weights by cards-remaining bucket, initialised from the neighbouring stage) is cheap in a LUT/NNUE design and was worth +35% at 3-ply in 2048; here early game (deck statistics dominate) and endgame (exact combinatorics dominate) are plausibly different functions.
- Blackjack evidence is weak/anecdotal, but the "counts confused the net" report is consistent with raw scalar counts being a poor encoding for a small MLP.

### Gaps
- Could not retrieve the input-feature lists for Skat (Rebstock et al., arXiv 1905.10911), bridge, Gin Rummy, Hearthstone or poker (DeepStack bucketing) within budget; no finding reported for them.
- No peer-reviewed source found on encoding exact deck composition for blackjack value approximation.
- No source found that tests NNUE-style nets on a card game; applicability is inference.
- The claim that the 250-point RMS floor is representational is unproven. A quick discriminating test (inference): overfit a few thousand exact labels with the current net. If it cannot drive training error near zero, suspect optimisation/target scaling (see section 4), not features.

## 3. Residual-on-heuristic learning, decomposed value heads, auxiliary heads

### Takeaway
Learning a correction on top of an analytical baseline, and adding auxiliary prediction targets that are "sub-components" of the final value, are both well supported: KataGo measured auxiliary targets as its single largest ablation (about 1.65x training efficiency), and residual learning is reported as markedly more data-efficient than learning from scratch when a decent baseline exists.

### Cited Findings
- Residual Policy Learning: "augment arbitrary initial policies by learning residuals on top of them"; works even when the base is non-differentiable; if the base is nearly perfect the residual is "a corrective term"; RPL "thrives in complex robotic manipulation tasks where good but imperfect controllers are available" — [Silver, Allen, Tenenbaum, Kaelbling 2018, arXiv 1812.06298](https://arxiv.org/pdf/1812.06298). Concurrent residual RL work by Johannink et al. is cited there.
- KataGo auxiliary targets: "although the game outcome is noisy and binary, it is a direct function of finer variables: the final score difference and the ownership of each board location. Decomposing the game result into these finer variables and predicting them as well should improve regularization"; described as a general heuristic that "predicting subcomponents of desired targets" helps — [Wu 2019, arXiv 1902.10565](https://arxiv.org/pdf/1902.10565)
- KataGo ablation (Elo after equal training / factor more training needed): baseline 1329 / 1.00x; without auxiliary ownership+score targets 1139 / 1.65x; without global pooling 1153 / 1.60x; without game-specific input features 1168 / 1.55x; without auxiliary policy target 1255 / 1.30x; without playout-cap randomisation 1242 / 1.37x. "Factors are approximate and are based on shorter runs" — [Wu 2019, Table 2](https://arxiv.org/pdf/1902.10565)
- KataGo overall: about a 50x reduction in self-play compute vs comparable AlphaZero-style efforts; handcrafted game-specific input features were themselves worth ~1.55x — [Wu 2019](https://arxiv.org/pdf/1902.10565)
- KataGo also predicts a full score distribution with pdf and cdf losses so mass is pushed "near the final score" — [Wu 2019](https://arxiv.org/pdf/1902.10565)
- Hand-made features on top of a learned n-tuple net were the strongest prior 2048 approach (Yeh et al.) — [Jaśkowski 2016, Table VI](https://arxiv.org/pdf/1604.05085)

### Inferences
- Residual target: V(s) = B(s) + g_theta(s), with B an analytical baseline. Candidate baselines, cheapest first: (a) banked score + sum over columns of exact single-column expected future points under the current deck (a small DP per column, table-driven by column state and deck); (b) value of a decoupled relaxation in which each column draws from its own copy of the deck (upper-bound flavoured, since it ignores competition for cards); (c) a greedy-rollout Monte Carlo estimate (too slow for leaf use, fine for labels). Initialise the output layer of g to zero so training starts at the baseline. If B captures most of the ~8,800-point scale, g only has to model a residual of a few hundred points, which directly attacks the 250 RMS problem by removing variance the net currently wastes capacity on.
- Decomposed head: V = banked + sum_i h(col_i, deck, globals) + interaction(pooled) + streak_term. Train with the total as the main loss; this is the Deep Sets architecture from section 1 with a physically meaningful split.
- Auxiliary heads that are cheap to label from the same exact endgame solver or from playouts: probability the game ends by third bust before the deck runs out; probability of zero further busts; expected number of remaining column clears; expected remaining streak bonus; expected number of Stays used; per-column probability of scoring before busting. Per KataGo, these act as regularisers and force the trunk to represent the variables the value is a function of. They cost nothing at inference if the heads are dropped.
- A hard-coded analytical baseline adds evaluation cost. A per-column table lookup keyed on (column state, relevant deck counts) is ~4 lookups; a full single-column DP against the live deck at each leaf would break the 20 microsecond budget unless cached per (column state, deck hash) in a transposition-style table.

### Gaps
- The quantitative RPL results (success-rate curves) were not extracted; only the qualitative claims above were verified.
- No source found for residual-on-heuristic VALUE learning specifically in stochastic card games; the KataGo and RPL evidence is by analogy.
- No published exact single-column value tables for this game variant; they would have to be computed.

## 4. Target / loss design for heavy-tailed scores

### Takeaway
Replacing scalar MSE with a categorical head (two-hot or Gaussian-smoothed "HL-Gauss" targets, optionally after an invertible squashing transform) is the best-evidenced loss change: it is reported as more robust to noisy targets and better at using capacity, with large gains in RL and in distilling a search engine's values. Evidence that it helps on clean supervised regression is weaker and mixed.

### Cited Findings
- MuZero: targets are scaled with the invertible transform h(x) = sign(x)(sqrt(|x|+1) - 1) + eps*x, eps = 0.001, then represented categorically on a support of size 601 (one per integer in -300..300); "each scalar is represented as the linear combination of its two adjacent supports" (e.g. 3.7 -> weight 0.3 on 3 and 0.7 on 4); the output is a softmax of size 601 and the value is recovered as the expectation followed by the inverse transform — [Schrittwieser et al. 2019, arXiv 1911.08265, Appendix](https://arxiv.org/pdf/1911.08265)
- Two-hot is "a uniquely identifiable and a non-lossy representation of the scalar"; HL-Gauss instead spreads mass over neighbouring bins from a Gaussian centred on the target ("akin to label smoothing"); recommended to tune the ratio sigma / bin-width — [Farebrother et al. 2024, arXiv 2403.03950](https://arxiv.org/pdf/2403.03950)
- Reported gains of HL-Gauss cross-entropy over MSE: "consistently 30% better performance" scaling Atari mixture-of-experts nets, 1.8-2.1x in multi-task Atari, 40% in a Wordle language-agent task, +67% robotic manipulation, and +70% on the "performance gap relative to the teacher Stockfish engine" for a 270M-parameter chess net distilled from Stockfish action-values — [Farebrother et al. 2024, Fig. 1 and intro](https://arxiv.org/pdf/2403.03950)
- Why: the benefits "primarily stem from its ability to mitigate issues inherent to value-based RL, such as noisy targets and non-stationarity"; with injected reward noise "performance of HL-Gauss degrades slower than MSE as noise increases" — [Farebrother et al. 2024](https://arxiv.org/pdf/2403.03950)
- In the chess distillation setup, "1-Hot targets outperform MSE on this task" (attributed to Ruoss et al.), and HL-Gauss improves further on 1-hot — [Farebrother et al. 2024, sec. 4.3.2](https://arxiv.org/pdf/2403.03950)
- Supervised regression: Imani & White report their distributional (histogram) loss "significantly improves prediction accuracy" and attribute it to the loss being "easier to optimize, with better behaved gradients", not to better representations — [Imani & White 2018, arXiv 1806.04613](https://arxiv.org/abs/1806.04613). Farebrother et al. characterise the same work as not finding "any representational benefits of HL-Gauss over MSE on supervised regression" and suggest the benefits may be specific to TD learning — [arXiv 2403.03950](https://arxiv.org/pdf/2403.03950). These are compatible (accuracy gain via optimisation, not representation) but indicate the gain on clean fixed labels is smaller than in RL.
- KataGo trains a score-distribution head with both pdf and cdf losses in addition to the scalar value — [Wu 2019](https://arxiv.org/pdf/1902.10565)
- Stockfish NNUE training: targets are squashed from centipawns into win-probability space with a sigmoid (scale ~400) before the loss; the loss exponent need not be 2 (Stockfish nets "trained well with an exponent of 2.6") — [nnue-pytorch docs](https://raw.githubusercontent.com/official-stockfish/nnue-pytorch/master/docs/nnue.md)

### Inferences
- First, change WHAT is predicted: predict remaining (future) score, not final score; the banked score is known exactly and should be added outside the net. If the current net predicts totals near 8,800, a large share of the 250 RMS may be plain scale/conditioning error. Combine with the residual baseline of section 3.
- Then a categorical head: e.g. 64-128 bins over the transformed remaining-score range, two-hot or HL-Gauss targets, cross-entropy loss, decode by expectation. Inference cost is one extra dense layer of 64-128 outputs plus a dot product (softmax needs exp per bin: ~100 exps is roughly 1-2 microseconds in JS; my estimate). To avoid exp entirely at search time, a second tiny scalar head can be distilled from the categorical one, or use the categorical head only as an auxiliary training loss.
- The score distribution here is heavy-tailed/bimodal (the game can end abruptly on the third bust; streak bonuses compound), so the conditional mean sits between modes. A categorical head represents that directly, and its tail mass gives the bust-out probability for free.
- For noise-free exact endgame labels the cited evidence predicts a modest, optimisation-related gain; for Monte Carlo rollout labels (noisy) it predicts a larger gain. Huber loss is the minimal-effort alternative for noisy labels.
- Caveat on transforms: with a squashing transform h, the network's expectation is taken in transformed space, so E[h^-1] differs from h^-1(E) when targets are noisy; this biases expectimax values that need true expected scores. With exact (noise-free) labels there is no such bias. Prefer a linear target scale with a categorical head if labels are noisy and unbiased means matter.

### Gaps
- I did not find or verify a source on Huber loss specifically improving value accuracy in games; no finding reported.
- DreamerV3's symlog + two-hot scheme is a closely related, widely used variant, but I did not fetch the paper (arXiv 2301.04104) this session, so no specifics are cited.
- No published evidence on categorical value heads for exact-label regression in solitaire/card games.

## 5. Search-side techniques that make better use of an imperfect value function

### Takeaway
For a single-player max/chance tree with at most 10 chance outcomes, full-width expectimax with a transposition table, time-based iterative deepening, and Star1/Star2-style chance-node bounds is the best-supported baseline; sampling methods (sparse sampling, MCTS with progressive widening) matter mainly when going deep. Noisy leaf values plus a max operator give a systematic upward bias, for which averaging several evaluators or shrinking estimates is the documented remedy.

### Cited Findings
**Expectimax pruning and transpositions**
- Star1 and Star2 (Ballard) "exploit a bounded heuristic evaluation function to generalize the alpha-beta pruning technique to chance nodes"; Star2 adds a probing phase that searches one child of each successor to obtain cheap lower bounds — [Veness & Blair 2007](https://cgi.cse.unsw.edu.au/~blair/pubs/2007VenessBlairCIG.pdf)
- In backgammon, Star2 "allows strong backgammon programs to conduct depth 5 full-width searches (up from 3) under tournament conditions on regular hardware without using risky forward pruning"; the same authors note that with strong evaluation functions good play "does not require deep searches" (via search summary of Hauk, Buro, Schaeffer 2004) — [*-Minimax Performance in Backgammon](https://papersdb.cs.ualberta.ca/~papersdb/view_publication.php?pub_id=824)
- Informal mailing-list figure from Hauk: on a synthetic board with backgammon-like branching, ~50.6 million nodes for Expectimax vs ~19.6 thousand for Star2 at ~2.5 ply (not from the paper; illustrative only) — [bug-gnubg list](https://lists.gnu.org/archive/html/bug-gnubg/2003-08/msg00428.html)
- Transposition tables can be used at chance nodes by storing independent upper and lower bounds. On 50 test positions of the game "Dice" searched to depth 13, mean cost was Expectimax 609.1, Star1 238.1, Star2 88.55, Star2-TT 60.83 (units garbled in my text extraction; appears to be time), and Star2-TT took about 31% less time than Star2 — [Veness & Blair 2007](https://cgi.cse.unsw.edu.au/~blair/pubs/2007VenessBlairCIG.pdf)

**Depth vs time, and evaluators inside search**
- 2048 n-tuple + expectimax: 1-ply 324,710; 2-ply 457,079; 3-ply 511,759; 5-ply 545,833 (16 moves/s); but time-limited iterative deepening does better per CPU: 1 ms/move 527,099 (916 moves/s), 50 ms 576,655 (20 moves/s), 100 ms 589,355, 1000 ms 609,104. "CPU time can be spent more effectively if we limit the time per move rather than the search tree depth" — [Jaśkowski 2016, Table V](https://arxiv.org/pdf/1604.05085)
- The evaluator that is best at 1-ply is not necessarily best at 3-ply ("1-ply overfitting"), and carousel shaping (starting training episodes from later-stage states) made 1-ply worse but 3-ply better (393k -> 433k) — [Jaśkowski 2016](https://arxiv.org/pdf/1604.05085)

**Sampling at chance nodes, MCTS**
- Sparse sampling (Kearns, Mansour, Ng): with only a generative model, near-optimal action choice with per-state running time independent of the number of states, at the price of exponential dependence on the horizon — [IJCAI 1999 / MLJ 2002](https://www.cis.upenn.edu/~mkearns/teaching/cis620/papers/sparseplan.pdf)
- Monte Carlo *-Minimax Search combines sparse sampling with *-minimax pruning for "densely stochastic" games; it "can be competitive with enhanced MCTS variants in some domains, while consistently outperforming the equivalent classic approaches given the same amount of thinking time" (tested on Pig, EinStein Würfelt Nicht!, Can't Stop, Ra; abstract only) — [Lanctot et al. 2013, arXiv 1304.6057](https://arxiv.org/abs/1304.6057)
- Double progressive widening (Couëtoux et al. 2011) caps the number of sampled children at about k*N^alpha on both the action and the chance-outcome side, trading variance against bias (search snippet + implementation docs) — [HAL hal-00542673](https://hal.archives-ouvertes.fr/hal-00542673v2), [MCTS.jl DPW docs](https://juliapomdp.github.io/MCTS.jl/dev/dpw)
- 2048: vanilla MCTS that does not model chance nodes scored ~34.7k vs ~57k for an MCTS-Expectimax variant with explicit expectation layers; a TD n-tuple agent scored ~131k with no lookahead and ~196k with expectimax (not budget-matched; search summary) — [arXiv 1907.06508](https://arxiv.org/pdf/1907.06508)

**Rollouts and variance reduction**
- Tesauro & Galperin: Monte Carlo rollouts on top of a base player gave "a substantial reduction, by as much as a factor of 5 or more, in the error rate of the base players", from random up to TD-Gammon; full rollouts with a strong net were too slow for real time (search snippet of the abstract/paper) — [NIPS 1996](https://proceedings.neurips.cc/paper/1996/hash/996009f2374006606f4c0b0fda878af1-Abstract.html)
- PEGASUS: any (PO)MDP can be transformed into an equivalent one in which all transitions are deterministic, which gives a natural way to estimate the value of all policies on the same scenarios, with polynomial rather than exponential dependence on horizon in the sample-complexity bounds (abstract; the usual reading is "fix the random numbers in advance", i.e. common random numbers) — [Ng & Jordan 2000, arXiv 1301.3878](https://arxiv.org/abs/1301.3878)

**Maximisation bias**
- Optimizer's curse: choosing the alternative with the highest estimated value leads to disappointment on average "even if the individual value estimates are conditionally unbiased"; more alternatives make it worse; the remedy is Bayesian shrinkage of estimates toward a prior mean (search summary; proof not re-read) — [Smith & Winkler 2006, Management Science](https://ideas.repec.org/a/inm/ormnsc/v52y2006i3p311-322.html)
- Double Q-learning: overestimation "result[s] from a positive bias that is introduced because Q-learning uses the maximum action value as an approximation for the maximum expected action value"; the double estimator may underestimate instead — [van Hasselt 2010, NeurIPS](https://proceedings.neurips.cc/paper/2010/hash/091d584fced301b442654dd8c23b3fc9-Abstract.html)
- Averaged-DQN: averaging K value estimates reduces target approximation-error variance, which translates into smaller overestimation bias; cost is K-fold more forward passes; larger K generally performed better (search summary) — [Anschel et al. 2017, arXiv 1611.01929](https://arxiv.org/pdf/1611.01929)

**Pondering**
- Pondering = using the opponent's thinking time to search the predicted reply; predictions are right "in about 50%" of cases (Hyatt); pondering also seeds the transposition table. No Elo figure given on the page — [Chessprogramming wiki](https://www.chessprogramming.org/Pondering)

### Inferences
- Chance nodes here have at most 10 distinct outcomes with known probabilities count[v]/N, so full-width expectation is cheap and exact; sparse sampling / progressive widening only become attractive beyond roughly depth 3-4, where 10^d x (up to 5 actions)^d explodes. A hybrid is natural: full width near the root, then sample the most probable outcomes (the ten-value has up to 16/52 mass) deeper, renormalising or using stratified sampling without replacement.
- Star1 is applicable: remaining score is bounded below by 0 and above by an optimistic bound (e.g. every remaining card scoring at the best rate, or the decoupled-relaxation value of section 3). After evaluating some outcomes at a chance node, the remaining probability mass times [L, U] bounds the node, and an action can be cut when its upper bound falls below the best action so far. Order outcomes by probability mass (tens first) to tighten bounds fastest. Gains depend on bound tightness; with a loose U the cutoffs will be rare, so the tight analytical bound is what makes this pay.
- Transposition table: this game transposes heavily (4! column orders x many deal orders reach the same canonical state). Hash the canonical (sorted columns, deck counts, busts, stays, streak) state; store exact values per depth. I expect this to be the single largest pure-search speedup, larger than in the cited Dice experiment, because the state is a small multiset.
- Time-based iterative deepening with TT, rather than fixed depth, per the 2048 result (50 ms beat fixed 5-ply while using less time per move).
- Selective deepening / "quiescence" analogue: extend the search by one ply at leaves that are "noisy" for the evaluator: a column one card from 21 or from five cards, a state with 2 busts, a live streak, or a forced-bust-or-Stay situation. Equivalent idea: only stop at leaves where no column is in a volatile state. This is my inference by analogy with chess quiescence; I found no source on quiescence for chance-node games.
- Maximisation bias in this tree: each max node picks over at most ~5 actions (4 columns, plus Stay options), each action value being a probability-weighted average of ~10 child evaluations. Averaging over chance outcomes reduces the independent part of the leaf error by roughly the square root of the effective number of outcomes, but errors correlated across siblings (systematic mis-evaluation of a state class) do not average out. With ~250 RMS leaf error and action-value gaps that are often smaller than that, optimiser's-curse bias and wrong-move selection are both plausible; deeper search compounds the upward bias at each max level.
- Mitigations in increasing cost: (i) reduce leaf error (sections 1-4), which is the dominant lever; (ii) average K = 2-4 independently initialised small nets at leaves (K-fold eval cost: affordable if a single net is ~3-5 microseconds; breaks the 20 microsecond budget beyond K ~ 4); (iii) double-estimator at the root only: pick the action with net A, report its value from net B; (iv) shrink leaf values toward the analytical baseline in proportion to estimated error variance (Smith-Winkler style); (v) at the root, break near-ties with common-random-number rollouts.
- Common random numbers are exact and natural here: the order of the remaining deck does not depend on the player's actions. To compare root actions, shuffle the remaining deck once per sample and play every candidate action against the SAME deck order with the same playout policy; score differences then have far lower variance than independent rollouts. Antithetic or stratified shuffles (stratify on the next 1-2 cards, which are enumerated exactly anyway) reduce variance further.
- Truncated rollouts: play d plies with the fast policy then evaluate with the net; averages out leaf noise along many trajectories (Tesauro's factor-5 error-rate reduction was for full rollouts; truncation is my extrapolation).
- Pondering in solitaire: there is no opponent, but the next card is a chance outcome with at most 10 values. While the user looks at the board or the UI animates, search each possible next card (most probable first) and store results in the TT; unlike chess's ~50% ponder-hit rate, coverage can be 100% of outcomes given enough idle time, and partial coverage still seeds the TT. In a browser this belongs in a Web Worker.
- MCTS vs expectimax: cited 2048 evidence favours explicit chance-node handling and expectimax with a good evaluator; MCMS reports beating classic *-minimax at equal time in densely stochastic games. For this game's low chance branching and small action set, I expect TT-backed expectimax to be hard to beat at short time budgets; an MCTS variant becomes interesting only for long-think modes.

### Gaps
- No source found on quiescence/selective extensions specifically for expectimax or single-player stochastic games.
- No rigorous, budget-matched MCTS-vs-expectimax comparison for a single-player card game was found.
- Exact node-reduction figures for Star1/Star2 in real backgammon (Hauk et al. tables) were not retrieved; only the depth-3-to-5 summary and an informal mailing-list number.
- No quantified Elo/score value of pondering was found.
- No source directly measuring optimiser's-curse bias inside expectimax with a learned evaluator; the link is by analogy from Q-learning and decision analysis.

## 6. Knowledge distillation from a slow strong player (deep search or exact solve) into a fast net

### Takeaway
Training the fast evaluator on targets produced by something stronger than itself (deeper search, re-searched old positions, an exact solver, or a stronger engine) is the standard recipe behind NNUE, MuZero Reanalyze and "searchless" chess; it reliably transfers much, though not all, of the teacher's strength, and blending search values with actual outcomes is common practice.

### Cited Findings
- Stockfish NNUE nets are "optimized and trained on the evaluations of millions of positions"; Stockfish 12 wins "at least ten times more game pairs than it loses" against the handcrafted-eval Stockfish 11 — [Stockfish 12 blog](https://stockfishchess.org/blog/2020/stockfish-12/)
- NNUE training target blends the teacher's search evaluation with the game result: wdl_value = lambda * wdl_eval + (1 - lambda) * game_result; whether to blend targets or losses "depends on your case" — [nnue-pytorch docs](https://raw.githubusercontent.com/official-stockfish/nnue-pytorch/master/docs/nnue.md)
- From June 2021 Stockfish's net was trained on Leela Chess Zero's openly released data (a stronger/slower evaluator's outputs); Stockfish 14 notes describe the collaboration; forum reports put the gain from Lc0 data at roughly +10 to +20 Elo, and one later net update adding more Leela data tested at about +2.7 Elo locally (forum/commit-message figures, not controlled studies) — [Stockfish 14 blog](https://stockfishchess.org/blog/2021/stockfish-14/), [Lc0 blog](https://draft.lczero.org/blog/2021/06/the-importance-of-open-data), [talkchess thread](https://talkchess.com/viewtopic.php?p=896060)
- Searchless chess: 10 million games annotated with Stockfish 16 action-values (15 billion data points per the follow-up paper), transformers up to 270M parameters, reaching Lichess blitz Elo 2895 against humans with no search; supervised learning distils "a remarkably good approximation of Stockfish's search-based algorithm" but "perfect distillation is still beyond reach" — [Ruoss et al. 2024, arXiv 2402.04494](https://arxiv.org/abs/2402.04494)
- The loss matters for distillation: HL-Gauss targets closed 70% more of the gap to the Stockfish teacher than one-hot targets for the 270M model, and one-hot already beat MSE — [Farebrother et al. 2024](https://arxiv.org/pdf/2403.03950)
- MuZero Reanalyze "revisits its past time-steps and re-executes its search using the latest model parameters" to produce fresh targets; it reached 731% median normalised Atari score at 200M frames vs 192%, 231% and 431% for previous state-of-the-art agents listed in the paper — [Schrittwieser et al. 2019](https://arxiv.org/pdf/1911.08265)
- Rollout targets: Monte Carlo search over a base player reduced its error rate by up to 5x or more, i.e. the slow rollout player is a much better teacher than the base net — [Tesauro & Galperin 1996](https://proceedings.neurips.cc/paper/1996/hash/996009f2374006606f4c0b0fda878af1-Abstract.html)
- Where states are sampled from matters: carousel shaping (restarting training from later-game states so late stages are visited more) improved 3-ply play (393k -> 433k) while slightly hurting 1-ply — [Jaśkowski 2016, Table IV](https://arxiv.org/pdf/1604.05085)
- KataGo's 50x efficiency gain came largely from better use of search-generated targets (playout-cap randomisation 1.37x, policy target pruning 1.25x) plus auxiliary targets — [Wu 2019](https://arxiv.org/pdf/1902.10565)

### Inferences
- Label ladder for this game: (1) exact values from the endgame solver wherever it reaches (noise-free anchor); (2) for earlier states, depth-d expectimax with the current net at the leaves, d larger than what will be used at play time; (3) common-random-number rollouts of the search player to the end of the game for an unbiased but noisy outcome. Blend (2) and (3) with a lambda as in NNUE: search values are low-variance but inherit net bias, outcomes are unbiased but noisy.
- Iterate ("reanalyse"): retrain the net, regenerate search labels with the improved net, repeat. Because exact endgame values are available, value accuracy can be bootstrapped backwards from the end of the game: train the stage with n cards left on search values whose leaves fall in the already-accurate stage with n - k cards (pairs naturally with stage-specific weights and weight promotion from section 2).
- Sample training states from the distribution the search actually visits at its leaves (states reached by the search player plus one or two exploratory/random moves), not only from greedy self-play; the 2048 "1-ply overfitting" and carousel results suggest evaluating every candidate net by score inside the real search, not by label RMS alone.
- Label generation is offline, so teacher cost is unconstrained; only the student must meet the 20 microsecond budget. A large, slow teacher net (or an ensemble) can also be distilled into the NNUE/LUT student.
- Expect diminishing returns per round (the Stockfish-on-Leela-data figures are single-digit to low-double-digit Elo once the pipeline is mature); the big step is the first move from weak labels to search/exact labels.

### Gaps
- No controlled measurement found of how much deeper-search labels (vs shallow or outcome-only labels) improve an NNUE-style net; Stockfish evidence is forum-level.
- KataGo's own distillation practice (training smaller nets from larger nets' data) was not researched this session.
- No literature found on backward bootstrapping from an exact endgame solver in a stochastic solitaire; the proposal is inference (it resembles retrograde analysis plus fitted value iteration).
